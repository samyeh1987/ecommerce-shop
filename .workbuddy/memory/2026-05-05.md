## 頁面跳轉問題修復 (13:30)

### 根本原因
`js/supabase-client.js` 只把函數掛在 `window.ThaiShop.*` 下，
但所有頁面 JS（index-thai.js, products.js 等）都直接呼叫全域函數名稱
（例如 `getProducts()` 而不是 `ThaiShop.getProducts()`），
導致所有 Supabase 相關功能都無法正常運作。

### 修復內容（Commit 4c0eae5）

1. **js/supabase-client.js**：在 window.ThaiShop 宣告區塊結尾，
   額外掛上全域 21 個函數（window.getProducts = getProducts; 等）

2. **pages/index-thai.html**：為 6 個分類卡片加上 onclick="navigateToCategory('xxx')"

3. **pages/js/index-thai.js**：
   - 加入 MOCK_CATEGORIES、MOCK_PRODUCTS 常數
   - loadCategories/loadFeaturedProducts/loadFlashSale 在無 Supabase 時改用 mock 資料渲染

4. **所有 HTML 頁面**（pages/*.html，共 7 個）：
   在 supabase-client.js 載入後插入全域暴露腳本：
   `<script>if(window.ThaiShop)Object.entries(window.ThaiShop).forEach(([k,v])=>window[k]=v);</script>`

## 頁面空白問題修復 (14:52)

### 問題
- 首頁整個頁面變空白
- 用戶回報 Vercel 部署頁面完全無內容

### 根本原因
CSS 語言切換規則 `.lang-zh, .lang-en, .lang-th { display: none !important; }` 會匹配到 `<body class="lang-zh">` 本身，導致整個 body 被隱藏！

### 修復內容（Commit 6a76fbd）

1. **所有 9 個 HTML 頁面**（index-thai, products, product-detail, cart, checkout, login, account, order-detail, admin-thai）：
   - CSS 選擇器從 `.lang-zh, .lang-en, .lang-th` → `body .lang-zh, body .lang-en, body .lang-th`
   - 加上 `body.lang-zh { display: block !important; }` 確保 body 本身可見

2. **pages/js/index-thai.js**：
   - `switchLanguage()` 新增 `document.body.style.display = 'block'`
   - `initLanguageFromStorage()` 確保初始化時 body 可見

3. **pages/index-thai.html**：
   - 新增 `body.lang-zh, body.lang-en, body.lang-th { display: block !important; }` 規則

### 經驗教訓
- CSS class 選擇器 `.lang-zh` 會匹配任何帶此 class 的元素，包括 body
- 多語言切換的隱藏規則必須用後代選擇器（`body .lang-zh`）避免匹配 body 自身
- 每個帶 `lang-zh` class 的元素都會被隱藏，body 也不例外
